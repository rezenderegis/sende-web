Sistemas não quebram de uma vez — eles vão ficando lentos, estranhos e cada vez mais caros de manter até que um dia param de acompanhar o negócio. O difícil é identificar o momento em que isso começou.

Alguns sinais são fáceis de notar. Telas que demoram mais para carregar à medida que a base de clientes cresce. Relatórios que precisam ser gerados "de madrugada" porque travam o sistema em horário comercial. Funcionalidades novas que levam cada vez mais tempo para serem implementadas, mesmo sendo simples — sinal de que o código virou um emaranhado difícil de tocar sem quebrar outra coisa.

Outros sinais são menos técnicos e mais organizacionais: a equipe criou planilhas paralelas "porque o sistema não dá conta", ou existe uma única pessoa capaz de resolver problemas porque conhece "os macetes" do sistema por fora.

## Quando isso vira risco real

O ponto de virada não é quando o sistema está lento — é quando ele começa a limitar decisões de negócio. Se você não abre uma nova unidade, não lança um produto ou não aumenta o time porque "o sistema não vai aguentar", o custo de não agir já é maior que o custo de reescrever ou escalar a arquitetura.

Fazer esse diagnóstico com antecedência custa muito menos do que fazer depois de uma parada não planejada.
